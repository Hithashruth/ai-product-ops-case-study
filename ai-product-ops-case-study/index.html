The opportunity is not “build every connector.”

Start where credentials are self-serve and the API is broad. The research set yields a large, high-confidence launch lane in developer, productivity, CRM, and commerce. The long tail is mostly real integration work - but access and safety, not endpoint availability, determine the order.

What the patterns say

1. OAuth is the operating system of SaaS. It dominates customer-facing SaaS, but “OAuth available” does not mean autonomous onboarding: org admin consent, app review, and scope design are repeated friction points.
2. Productivity + developer tools are the cleanest wedge. Their APIs are documented, broad, and usually self-serve; they also map naturally to high-value read/search/create agent actions.
3. The most common blocker is access, not documentation. Enterprise data products, ads, marketplaces, payments, and support systems usually expose APIs but impose admin, plan, compliance, or production-approval gates.
4. MCP is a distribution signal, not a quality guarantee. It accelerates discovery and prototyping, but production toolkits still need scope minimisation, typed actions, rate-limit handling, and auditability.

The research agent

A repeatable evidence loop rather than a one-off spreadsheet.

01 · SeedLoad the 100 named apps and a canonical official-docs starting URL.
02 · BrowseFetch docs; capture auth, access, API and MCP evidence with the URL.
03 · ExtractReturn constrained JSON. No source URL or uncertainty marker means no accepted claim.
04 · ValidateSchema checks, URL checks, enum checks, and duplicate/conflict review queue.
05 · Human reviewSpot-check ambiguous, gated, high-risk, and surprising records against primary docs.

Runnable proof: python research_agent.py --check-links validates all record schemas and emits a per-source evidence-status report. The pipeline intentionally leaves blocked/ambiguous sources reviewable instead of fabricating certainty.
